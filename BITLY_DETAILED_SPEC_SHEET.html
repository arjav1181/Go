01 · Product overview

Product definition and scope

Bitly is a link-management and engagement platform, not just a URL shortening endpoint. Its connected products cover short URLs, managed QR Codes, shareable mini-sites, campaign organization, event analytics, custom domains, and developer access.

Bitly Links

Shorten long web URLs; use generated or custom back-halves; organize and update destinations; measure clicks; connect QR Codes, tags, campaigns, domains, and pages.

Bitly Codes

Create QR Codes for URLs, Bitlinks, pages, and supported static data. Customize visual appearance; export files; measure scans for managed codes.

Bitly Pages

Publish mobile-friendly landing pages / link-in-bio pages from templates or a blank page, with editable blocks, scheduled content, themes, and engagement reporting.

Campaigns

Group campaign links by distribution channel and apply UTM tagging so activity can be compared between channels.

Analytics

Aggregate engagements by time, referrer, geography, device, asset, page, and campaign where the plan supports the report.

Platform & API

Browser app, mobile apps, browser extensions, API v4, integrations, team administration, custom domains, and Enterprise governance.

Shared interaction pattern inventory

Search and filters

Global search is available across the app except in settings. Link/QR search matches URL, short URL, title; search/filter scope follows the active group.

Bulk selection

Selected links can be managed in bulk where the action and subscription allow it. Selective link export is limited to 100 links per export in the cited help guide.

More-actions menus

Existing assets expose context-dependent actions such as edit, share, expiry, copy, duplicate design, add to page, export, or status controls.

Draft vs published

Page changes persist as a draft; public changes do not go live until “Publish changes” is selected.

Scheduling controls

Bitly Pages content blocks may be scheduled to appear and/or unpublish at a selected date/time. Scheduled or disabled page links are not shown in the public preview.

Usage and upgrade messaging

Creation quotas and plan-locked capabilities are exposed through usage views and in-product upgrade prompts; limits are separate from click/scan traffic limits.

Export behaviors

  • Link list exports include link, custom link (if used), created date, title, destination URL, engagements for the available plan window, and status.
  • For selective exports, the documented maximum is up to 100 links at a time; selected-list exports include Bitlink, custom Bitlink, long URL, clicks, and status.
  • Large full-account link exports are emailed; the support article warns large exports can take up to 30 minutes.

Custom back-half syntax

Maximum length
255 characters.
Allowed characters
A–Z, a–z, 0–9, hyphen -, underscore _.
Disallowed examples
Spaces, slashes, periods, colons, percent signs, query/hash separators, brackets, many punctuation/symbol characters.
Case behavior
Case-sensitive. The same exact custom back-half cannot be reused; capitalization variants may be treated as separate links.
Uniqueness
Custom slug must be unique under the chosen domain; conflicts require a different back-half or domain.
Documented Bitly links are case-sensitive. Its support guide specifies the supported back-half characters and a 255-character limit. Character support reference ↗

Link list details and controls

Searchable fields

Destination URL, short link/back-half, and title; global search can be used from multiple app sections.

Filtering

Creation date and additional link filters. Filters are applied within the current active group.

Metadata

Short link, destination, title, creation details, status, optional tags/custom link, and engagement counts.

Editing and redirect

Changing the destination is distinct from editing metadata. Destination redirect actions use separate plan quotas in the pricing comparison.

QR association

A QR Code can use an existing Bitlink as its destination, which makes redirecting the short link useful for printed material.

Old destination / link history

Bitly’s public best-practice guide says older versions can continue to work after a link is edited; multiple short URLs can point to the same destination.

Creation and metadata semantics

  • Bitly’s public shorten endpoint accepts a required long_url, an optional domain (default bit.ly), group_guid, and force_new_link.
  • The link identifier returned by the API includes the domain and short code; a short URL is not merely a text transformation—the system maintains a destination mapping.
  • The public API distinguishes link creation/shortening, reading existing links, expanding a short link to a long URL, and changing an existing destination.
  • Destination edits, link/QR expiration, branded-domain availability, and link quotas are separate lifecycle/entitlement dimensions.

Active valid BitlinkRedirects to saved destinationDestination may be edited on eligible plans; clicks continue to accumulate against the managed link/asset.
Destination editedRedirect target changes while using a short-link identityBitly’s support best-practice page says older versions can continue to work after editing; redirect changes have plan quotas.
Expired link or codeRedirects to Bitly’s 410 page or custom error page, depending on configurationHistorical analytics remains; new engagement stops. An expired link can be reactivated; the help page says it cannot be deleted while expired.

Deleted/hidden/inactive itemUI and API represent status for some asset operationsPrecise retention and all state transitions vary by feature; not every internal status is public.

Expiration rules

  • Available on some paid plans.
  • Can be configured during link/QR creation via Advanced Settings, or on an existing asset through a more-actions menu.
  • Minimum lead time in the cited help documentation: 5 minutes; maximum: 1 year from current time.
  • On expiry, the visitor gets an error destination/page rather than the original content; Bitly describes a 410 page or custom error page.
  • Historical analytics is retained; no new clicks/scans are recorded after expiration.
  • Expiration survives destination edits and custom-back-half changes; coupled QR Code expiry follows the link.
  • Expiration must be individually set; the cited support article says bulk expiry is not currently supported.
  • Expired links cannot be added to campaigns, new QR Codes, or Pages until reactivated.
Boundary Public docs describe product behavior but do not guarantee a single redirect HTTP status code, cache policy, latency, or edge-routing implementation for every active link. Only the expiration behavior above explicitly mentions a 410 page.

Sources: Link/QR expiration help, link re-use and capitalization best practices, redirect quotas by plan.

QR management and analytics

  • QR Codes can be searched via global search or the QR Codes section; matching fields include long URL, short link, and title.
  • Filters documented for QR Codes include created date, code type (QR Code / 2D barcode), creator, attached link, and expiry status (expired, expiring, no expiration date).
  • Scan counts are advertised as unlimited across standard plans; creating new codes is limited by monthly quota.
  • QR Codes and links can be independently created under particular flows; a stand-alone QR created with long_url rather than a bitlink_id consumes QR-code quota without consuming link quota, according to the developer tutorial.
  • For managed codes, the API can return QR metadata such as ID, group, title, archived state, created time, and modified time.
  • QR analytics may include time, location, referrer/source, and device breakdowns on eligible tiers.

Page design and scheduling

  • Templates include link-in-bio, products/services, and promotions use cases; the page can also start from a blank slate.
  • Design controls include theme/layout choices and profile/background imagery, with a public/mobile preview.

Campaign analytics

  • Campaign views summarize total engagements and can show number of channels and links.
  • Channel details can show engagement counts and time series side-by-side to compare distribution performance.
  • Users can drill from channel detail into an individual link’s detail page.
  • Campaign data and link analytics are related but not identical; campaign views aggregate channel assets, while individual link detail exposes asset-level dimensions.
  • Campaign creation, channel reporting, campaign-level tracking, bulk import and export are plan-dependent. Premium pricing advertises custom campaign-level tracking.

Date windows and data retention

  • Analytics defaults may show the last seven days in documented dashboard flows, with a selectable date range.
  • Maximum historical duration is plan-dependent; the standard pricing comparison lists 30 days (Core), 120 days (Growth), one year (Premium) and two years (Enterprise) for analytics history.
  • The link details view may show engagement totals for the maximum period available to the subscription, not lifetime totals; date range selection changes charts and supported breakdowns.
  • Changing a Page’s selected date period also changes the maximum history scope subject to plan eligibility.
  • Dashboard modules can be customized; the support docs say changes are automatically saved as users edit modules.

Export / delivery

  • Export options include link-level records and analytics aggregate data; fields differ by export function.
  • Some exports are downloaded directly; full data exports can be processed asynchronously and emailed to the account holder.
  • API analytics endpoints return date-bucketed counts for a supplied time unit and number of units.

Privacy interpretation notes

  • Short-link analytics are interaction analytics: visitors click a link or scan a code, and the service records engagement information to provide reporting.
  • Referrer information is not complete for every click. Email, SMS, direct browser entry and certain apps may be attributed to Direct or another source category.
  • Location is derived from available networking/location signals and should not be interpreted as exact GPS location.
  • Privacy policy descriptions may include IP-derived location, device/browser information and timestamps. A platform using link analytics must communicate its own data practice clearly.
Public privacy/security descriptions do not reveal Bitly’s entire event schema, bot-filtering logic, raw-data retention schedule, or internal abuse-scoring implementation. Those details should not be inferred from visible charts or API output.

17 · Boundaries of public documentation

Universal redirect status and cache headersExpiration help specifies a 410 page/error page; a universal status/header policy for all requests is not established in sources reviewed.
Guaranteed redirect latency or global throughputEnterprise pricing advertises a 99.99% uptime SLA; universal redirect latency and throughput numbers are not established here.
Exact unique-user/session modelPublic reports expose clicks/scans and breakdowns, but this review does not establish a universal cross-product unique-user identity definition.
Raw event retention and deletion schedulePricing specifies analytics history windows; this is not necessarily the same thing as a complete underlying raw-event retention schedule.

All API scopes/rate thresholdsPublic API docs and account quotas describe supported operations and usage limits; thresholds and available features can vary by account/contract and change over time.
Every UI screen at every account tierPublic screenshots are representative. UI controls differ by plan, group role, rollout, and whether a feature is enabled.
